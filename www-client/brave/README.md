
## www-client/brave (Brave built from source)

`www-client/brave` is Brave built from brave-core + Chromium with the **system** clang/lld/rust toolchain
(modelled on ::gentoo's `www-client/chromium`). `www-client/brave-bin` is the upstream binary. They install
side by side with no file collisions (brave: `/usr/lib64/brave`, `/usr/bin/brave`, `brave-browser.desktop`;
brave-bin: `/opt/brave.com`, `/usr/bin/brave-bin`, `brave-browser-stable.desktop`) and are not blocked, but
**both use the profile `~/.config/BraveSoftware/Brave-Browser`**: don't run them at once and don't downgrade.

- **Version policy.** The ebuild builds only against the Chromium that ::gentoo's `www-client/chromium`
  packages (same chromium-linux tarball, same `chromium-patches-N`, same LLVM slot). `PV` is the newest Brave
  *release* pinning that Chromium: `.ci/brave-source-latest.py` (nvchecker) prints it. Currently 1.93.137
  (Chromium 151.0.7922.169); `brave-bin` is newer (1.98.62, Chromium 156) because ::gentoo has no 156 yet.
  A security-fix gap vs brave-bin is expected; use brave-bin when you need the latest Brave.
- **Distfiles** (network-free build): the Chromium tarball + patchset come from their usual hosts;
  `brave-core-PV.tar.xz`, `brave-deps-PV.tar.xz` (brave-core DEPS git deps + npm node_modules incl. the
  @brave/leo build) are generated by `.ci/make-brave-distfiles.sh PV` and kept in a **private** Forgejo
  release (`CanuteTheGreat/gentoo-submissions`, tag `brave-PV`). Portage can't fetch a private URL: put the two
  files into `DISTDIR` (`/var/cache/distfiles`) before `emerge`. `rust-std` (wasm32) comes from static.rust-lang.org.
- **Sandbox.** `chrome-sandbox` is installed setuid root (4755) in `/usr/lib64/brave/`, like ::gentoo's chromium;
  Brave uses the user-namespace sandbox when the kernel allows it (USER_NS, PID_NS, NET_NS, SECCOMP_FILTER) and
  falls back to the setuid helper otherwise. `pkg_postinst` verifies the mode, `pkg_setup` checks the kernel
  config. Never run with `--no-sandbox`.
- **Keys.** No private Brave service keys: the build is `is_official_build=false` with Brave's public defaults
  (Brave's official build asserts that keys are set), so key-gated services are inert.
- **Cost.** One build per Brave release: ~DISK GB scratch, ~RAM GB peak RAM, ~TIME on 8 shared vCPUs
  (see "Build record" below); the overlay manager runs it at most once per release, overnight, on an idle rw-man
  host (gentoo-overlay-maintenance skill).
- **Bump = ** `.ci/make-brave-distfiles.sh NEW` -> upload to the release -> `git mv` the ebuild, set `CHROMIUM_PV`/`PATCH_V` to
  ::gentoo's chromium -> `ebuild … manifest` -> stage3 container build with the network disconnected -> smoke test.
- **Risks.** Brave's patch set and build scripts change shape (the version/branding steps are re-implemented
  from `version.py`/`branding.js`); ::gentoo's patchset can lag or drop; bundled libs (keeplibs list in the
  ebuild = chromium's) change every Chromium major; upstream may start requiring keys or the bundled toolchain.
